# Triggers for maintain-skills

## Should fire

- audit the skills and see what has gone stale
- do a maintenance pass over the stack
- our AGENTS.md still describes the old service layout, check the rest of it
- the agent kept following a rule that has not been true for months, find the others
- I added six skills this month, are the earlier ones still consistent with them
- refresh the agent context in this repo before I hand it to the team

## Should not fire

- clean up the wording in this skill. `unslop-prose` owns prose quality; this pass is about
  claims that stopped being true, not sentences that read badly.
- mine my last few sessions and remember how I like to work. `continual-learning` owns
  durable facts about the user, and routes standards-worthy lessons onward.
- add a skill for handling flaky tests. `thiamine-author` owns creating and changing
  artifacts. This skill decides what needs changing and hands the edit over.
- this repo has three different date libraries, pick one. `consistency` owns how many
  answers a concern gets in the code. This owns whether the context describes the code.
- run the validator. That is one step of this pass, not the pass. Run it directly when the
  mechanical check is all you want.
