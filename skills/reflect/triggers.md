# Triggers for reflect

## Should fire

- reflect on this session and see what we should turn into a skill
- that took all day and a lot of wrong turns, capture it so the next one does not
- we have now solved this same problem twice, make it repeatable
- go through the last few sessions on this repo and pull out what belongs in the stack
- the build is done, what did we learn that should be written down as a standard
- turn what we just figured out into a skill

## Should not fire

- remember that I prefer uv over pip. `continual-learning` owns durable facts about the
  user and the project, which belong in memory. This owns how work gets done.
- where did I leave off yesterday. `handoff` owns the record of work in progress and
  reconstructing it. Reflection happens after work lands, not to resume it.
- audit the skills for anything that has gone stale. `drift-audit` works from the corpus
  and looks for claims that stopped being true. This works from sessions and looks for
  knowledge that was never captured.
- add a skill for handling flaky tests. `thiamine-author` owns writing the artifact. This
  decides what is worth writing and hands it over.
- summarize what we did today. The deliverable here is a capability, not a retrospective.
