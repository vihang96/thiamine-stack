# Triggers for working-style

## Should fire

- automate me
- capture how I like to work into a skill agents will follow
- update my mode skill, I have changed how I want PRs handled
- you keep summarizing output instead of pasting it, record that somewhere permanent
- make a vihang-mode skill from how I have been working this month
- I should not have to repeat this preference every session

## Should not fire

- remember that I work at Kognitos and use uv. `continual-learning` owns facts about the
  user and the project, which go to memory. This owns behaviour an agent should follow.
- that approach worked, turn it into a skill. `reflect` owns methods, which are true no
  matter who is asking. This owns preferences, which stop being true for a different person.
- this repo uses tabs and 100 columns. That is the repo's convention and belongs in its own
  `AGENTS.md`, not in a file describing a person.
- add a skill for triaging review comments. `thiamine-author` owns writing artifacts. This
  decides what one person's taste is and hands the file over.
- capture how I write commit messages. One narrow workflow is an ordinary skill, not a mode
  skill, and needs no mining. A mode skill describes a whole way of working.
